## J001 — Home capability truth
Owner: Worker A.
Acceptance: remove stale renderer/Create wording; Home must reflect live capability state and expose real Create.

## J002 — Global + workspace navigation
Owner: Worker A.

## J003 — Deferred-surface honesty
Owner: Worker A.
Acceptance: Following, Clips, Notes and Audit are either backed or clearly unavailable with a useful next action; no misleading dead ends.

## J004 — Unified multi-reality Create
Owner: Worker C.
Acceptance: one browser submission can request Original, Tactical, 3D Game and Anime/NPR and produces one render plan; no manual API dispatch.

## J005 — Compute Connection Center
Owner: Worker B + Worker C.

## J006 — Compute transparency
Owner: Worker C.
Acceptance: Create and Watch show compute source, provider, selection reason, measured allowance/cost, privacy posture and fallback state.

## J007 — Durable public control plane
Owner: Worker B.
Acceptance: Neon/R2 persistence; create on instance A and read on instance B; redeploy does not erase sessions/results; Library/Jobs/Watch recover without developer intervention.

## J008 — Rights Holder edit/revoke
Owner: Worker B + Worker A.
Acceptance: edit rights, re-derive capabilities, verify revoked playback/publication fails closed, record the change in audit.

## J009 — Rights/audit discoverability
Owner: Worker A + Worker B.
Acceptance: Rights Holder and Operator can reach the relevant audit trails from their workspaces without guessing URLs.

## J010 — Analyst Clips/Notes minimum
Owner: Worker A.
Acceptance: save actual media-time markers/clips where backed, attach notes, revisit them; no fake clip bytes.

## J011 — Operator contextual navigation
Owner: Worker A.
Acceptance: Operations jobs/failures link directly to affected session, Watch, Create/job details and relevant provider state.

## J012 — Reality-fidelity production path
Owner: Worker A + Worker C.
Acceptance: supported real footage produces meaningful entities/events; materially different clips yield materially different reconstructed football states; empty/default SWM cannot pass the final derived-reality gate.

## J013 — Derived-reality sensitivity gate
Owner: Worker C.
Acceptance: meaningful SWM differences change Tactical/3D/Anime outputs; byte-identical outputs require an explicit equivalence explanation.

## J014 — Clean-browser restart/redeploy acceptance
Owner: Worker B + Tech Lead.
Acceptance: user/session/artifacts survive restart/redeploy; Watch and Library recover; public path has no hidden in-memory dependency.

## J015 — Final journey acceptance
Owner: Tech Lead.
Acceptance journey:

fresh browser -> sign up -> Creator -> Create -> real upload -> rights -> select realities -> choose/connect compute -> submit once -> real processing -> four outputs -> Watch -> switch realities -> Library/Jobs -> role switch -> refresh/redeploy -> return to result.

No developer API calls, manual DB edits or fixture sessions.

## Completion rule

A journey item is complete only when the user-visible boundary is verified. Passing unit tests alone is insufficient.
