## Program A — User Journey Hardening

J001-J015 remains required for the public batch MVP:
discoverability, multi-reality Create, compute center, durability, rights, role surfaces, perception fidelity and final clean-browser journey.

## Program B — Live Reality

### L0 — shared contracts

Freeze live observation, world-state, watermark, temporal buffering and live renderer contracts.

### L1 — deterministic live loop

Implement a replayable/synthetic live tracking stream and drive the real SWM incrementally.

### L2 — live tactical reality

Render the live SWM in a browser at interactive frame rate with explicit latency/quality telemetry.

### L3 — public tracking-data benchmark

Use a legally permitted public/open tracking dataset for replay benchmarking, including SkillCorner where its data terms permit the intended use.

### L4 — provider adapter

Add at least one real authorized tracking-provider adapter behind the Compute/Technology boundaries when credentials/data access are available.

### L5 — broadcast reconstruction

Benchmark real-time broadcast perception candidates independently from the renderer and tracking-feed path.

### L6 — multi-source fusion

Allow tracking and broadcast perception evidence to coexist, with explicit confidence/provenance and recovery semantics.

### L7 — live 3D

Make the existing 3D renderer consume the same live SWM without creating a second canonical state model.

### L8 — live/replay continuity

Persist enough live data/state to replay, seek and inspect the same match after the live window closes.

## Final shared gates

R606: human visual acceptance of batch realities.

R607: public batch MVP journey.

L015: live tactical latency/continuity gate.

L016: live tracking -> SWM -> tactical browser journey.

L017: live-to-replay continuity and recovery gate.

No final gate may pass on avatar motion alone; meaningful state, temporal integrity, provenance and observed latency must be evidenced.
